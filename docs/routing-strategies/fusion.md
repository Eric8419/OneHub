# 多模型融合（`fusion`）

## 行为

多模型融合不是只选择一个目标，而是按目标优先级建立执行计划：

1. 最高优先级目标作为 judge。
2. 其余目标作为 panel，最多 8 个，并行发起非流式请求。
3. 收集可用回答，附加到原请求中交给 judge。
4. judge 综合矛盾和独有信息，返回最终答案。

原请求如果是流式，只有最后的 judge 响应流式返回；panel 请求始终非流式。

## 适用场景

- 需要多个模型交叉验证、比较或集成答案。
- 有一个更强的模型负责最终审阅，其他模型负责提供候选答案。

## 注意事项

需要工具调用时，为避免并行 panel 的工具副作用，代理会退回普通单目标路由。所有 panel 都没有可用回答时返回网关错误；融合也会放大请求数和成本。
