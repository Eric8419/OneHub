# 上下文优化（`context-optimized`）

## 行为

根据请求的上下文 Token 估算值筛选模型，并在能容纳请求的候选中选择最小的 `contextWindow`，减少为小请求使用超大上下文模型的浪费。

路由前已经过滤不满足请求能力或上下文窗口的目标；如果没有任何目标能容纳当前请求，代理会返回无可用目标，而不是强行超限发送。

## 适用场景

- 同一聚合包含不同上下文窗口的模型。
- 希望小请求走更便宜或更快的模型，大请求自动升级。

## 注意事项

上下文 Token 是快速估算值，最终限制仍由上游模型执行。目标都能容纳请求时，策略只比较窗口大小，不比较价格或延迟。
